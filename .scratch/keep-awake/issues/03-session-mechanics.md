# Session mechanics for an accessory SwiftPM app: notifications, deadline timers, menu bar countdown

Type: research
Status: resolved
Blocked by: None — can start immediately

## Question

Three platform facts gate the spec's Session lifecycle ([map](../map.md) decisions 6, 10, 11). Medusa is an `LSUIElement`-style accessory (`NSApp.setActivationPolicy(.accessory)`), built by SwiftPM and bundled by `scripts/build-app.sh` (bundle id `org.medusa.Medusa` / `.local`), macOS 13 deployment target, also run **unbundled** via `swift run` and the `--self-test` harness. From Apple docs and sample code:

1. **UserNotifications from this app.** Requirements for `UNUserNotificationCenter` (a real bundle id — what happens unbundled? does `current()` trap?), requesting authorization from a menu-bar app, showing while our app is "frontmost" (delegate `willPresent`), **actionable notifications** ("Extend 30 min" button via `UNNotificationCategory`/`UNNotificationAction`) and handling the action while the app runs, and whether a `Provisional` authorization avoids the prompt. Note anything Sparkle or `.accessory` policy changes. Fallback if notifications are denied (menu-only state).
2. **Deadline timers across sleep.** Behavior of `Timer`, `DispatchSourceTimer`, and `DispatchQueue.asyncAfter(wallDeadline:)` when the Mac sleeps past the fire time — do they fire on wake? Recommended pattern for "end the Session at absolute time T": store the deadline `Date`, arm a wall-clock timer, and re-evaluate on `NSWorkspace.didWakeNotification` (+ any clock-change notification, `NSSystemClockDidChange`). Precision needed: ±2 s.
3. **Menu bar countdown & state icon.** Updating `NSStatusItem.button.title` beside the image (monospaced digits via `NSFont.monospacedDigitSystemFont`, `imagePosition`, avoiding width jitter), sensible refresh cadence (per minute above 1 min, per second below), and SF Symbols available on **macOS 13** that read as awake / locked / idle next to the current `eye.trianglebadge.exclamationmark` (candidates: `cup.and.saucer`, `bolt`, `eye`, `moon.zzz`, `powersleep` — verify availability and template rendering). Also the cleanest way to present "Until…" and "Custom…" pickers from a menu item (an `NSPopover`/small `NSPanel` with `NSDatePicker`, or SwiftUI `DatePicker` hosted in a panel).

Deliver in `../research/03-session-mechanics.md`: a recipe for each of the three (API, macOS 13 caveats, the unbundled guard), and flag anything that changes decisions 6, 10 or 11. Cite every claim.

## Answer

All three are feasible. Findings: [`../research/03-session-mechanics.md`](../research/03-session-mechanics.md).

1. **Notifications.** `UNUserNotificationCenter.current()` **hard-traps** unbundled — reproduced locally: `NSInternalInconsistencyException: bundleProxyForCurrentProcess is nil`, thrown from a `dispatch_once` inside `+currentNotificationCenter`, so it is uncatchable and unretryable. Guard everything on `Bundle.main.bundleIdentifier != nil`; a plain `CFBundleIdentifier` is the *only* requirement (ad-hoc signed, unregistered, outside `/Applications` all work — verified). `LSUIElement`/`.accessory` is irrelevant, and Sparkle contains zero UserNotifications references, so no collision. Delegate + `setNotificationCategories` must run **at launch**; `requestAuthorization` stays at first Session start. **Provisional authorization is ruled out** — it suppresses banners entirely, so "Ending in 5 min → Extend" would only exist in Notification Center history. `willPresent` must be implemented (returning `[.banner, .list, .sound]`) or notifications are silenced whenever Medusa is active. Denial → menu-only, one latched alert, greyed toggles.
2. **Deadline timers.** Apple DTS, verbatim: both `Timer` and `DispatchSourceTimer` "rely on Mach absolute time. This stops counting when the CPU stops, that is, when the device sleeps." `wallDeadline:` is documented as `gettimeofday`-based but is not a promise to build on. So: absolute `Date` is the only state, a self-correcting tick that re-reads `Date()` is the authority, and `NSWorkspace.didWakeNotification` **plus `NSSystemClockDidChange`** force immediate re-evaluation. ±2 s falls out of a ≤1 s tick for free.
3. **Menu bar.** Every candidate symbol is macOS 13-safe (verified against `CoreGlyphs.bundle/name_availability.plist`; none restricted) except `cup.and.heat.waves` (2024). Proposed: `cup.and.saucer.fill` awake / `lock.fill` locked / today's `eye.trianglebadge.exclamationmark` idle. Monospaced digits alone do **not** stop width jitter — the fixed-width `1:23` format does; keep `1 h 23 m` for the menu header only. Use `imagePosition = .imageLeading` + `imageHugsTitle`. Minute-cadence refresh must land on the countdown's own minute boundary, else the number reads up to 59 s stale. "Until…"/"Custom…" → `NSAlert` + `accessoryView` + `NSDatePicker`, the pattern `AppDelegate` already runs twice; `NSPopover` is post-v1 polish.

**Decisions:** 6 confirmed and hardened (add `NSSystemClockDidChange`; the tick, not the one-shot timer, is authority). 10 confirmed with three refinements (launch-time delegate/categories; no provisional; the menu's `Extend ▸` is the guaranteed path since Banners-vs-Alerts is the user's setting). 11 confirmed with one correction (format, not font, fixes jitter) and one addition (boundary-aligned minute tick). No change to `build-app.sh`, `Info.plist`, signing, or the release pipeline. One new codebase invariant: nothing touches `UNUserNotificationCenter` without the bundle-id guard, or `swift run` and every `--self-test`/`--snapshot-*` entry point dies.
