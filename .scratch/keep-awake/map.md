# Map: Keep Awake sessions

## Destination — REACHED 2026-09-07 (v0.3.0)

### Charting decisions (self-grilled, delegated)

1. **Destination shape** — spec **and** ship in one map, not spec-only. _Why_: every prior effort here did; the ask is "clone the feature", not "write about it".
2. **Product identity** — Keep Awake is a **peer of the Lock**, not a lock option: its own menu section, its own Settings tab. _Why_: the README already sells "keeps your Mac awake so long work keeps going"; the Lock is the shield, Keep Awake is the engine — same job, two tools.
3. **Model: one engine, many Holds** — a single keep-awake engine holds the OS assertion while **any** Hold is live. Holds: user **Sessions** and the **Lock hold**. Rejected: independent assertions per feature (two sources of truth), and "the lock adopts the session's horizon" (silently ending a promise the user made via the lock toggle). _Consequence_: `LockController` stops owning `PowerAssertion` and instead places/withdraws a Lock hold. The menu shows every live Hold so nothing is hidden.
4. **Awake levels** — **Display awake** (screen on; today's behavior) and **System awake** (screen may sleep, Mac keeps computing). Strongest live level wins. Session default: Display awake (Amphetamine parity, Medusa's "screen visible" pitch), per-session override + Settings default. Lock hold is always Display awake (the Shield must be visible). **Research 01 confirmed** the mapping: Display awake = `PreventUserIdleDisplaySleep` (header-documented to also block idle system sleep) — and, like Amphetamine, hold `PreventUserIdleSystemSleep` **alongside** it so `pmset -g assertions` is self-documenting; System awake = `PreventUserIdleSystemSleep` alone. `PreventSystemSleep` is deprecated and never used. Neither level survives lid close, low battery, or Apple menu → Sleep.
5. **End conditions v1** — Indefinitely · For a duration (presets + custom h/m) · Until a clock time. **"While an app/process is running"** is decided in ticket 05 after research 04 — Medusa's audience runs `claude`/`codex`/`xcodebuild`, so a CLI-aware version would beat Amphetamine.
6. **Deadlines, not stopwatches** — a duration becomes an absolute end time at start. Forced sleep (lid) can't be prevented by idle assertions; on wake, a passed deadline ends the Session, otherwise the Hold is reaffirmed (existing `PowerAssertion.reaffirm` precedent). **Research 01**: whether the kernel's assertion timeout counts sleep time is undocumented, so the absolute deadline is the **only** clock and the timeout is re-derived from `deadline − now` on every wake. **Research 03**: `Timer` and `DispatchSourceTimer` run on Mach absolute time, which **stops during sleep** (Apple DTS, verbatim), and `wallDeadline:` is a hint not a wake guarantee — so a ≤ 1 s self-correcting tick that re-reads `Date()` is the authority, re-evaluated on `NSWorkspace.didWakeNotification` **and** `NSSystemClockDidChange`. **Research 02**: Amphetamine exposes this as a preference ("Use timer / Use system clock") because users wanted the stopwatch reading; Medusa keeps the deadline **hardcoded** (simpler, honest about the real end time) and answers the "my 3-hour session lost an hour while the lid was shut" complaint in the ended-notification copy: `End time (4:00 PM) passed while your Mac slept`.
7. **Session ↔ Lock composition** — locking during a Session adds the Lock hold; unlocking removes only it. A Session ending under Lock changes nothing while the Lock hold stands; with the lock toggle off, the display sleeps on schedule and the existing System-lock yield/release path applies — no new path. Sessions start only while unlocked (the menu isn't reachable under the Shield; keep-awake hotkey is ignored while locked). Preempt idle auto-lock is **not** paused by a Session (stepping away should still shield input).
8. **No persistence** — a Session dies with the process; quitting ends every Hold, no confirmation dialog. Recovery lever: **"Start Keep Awake when Medusa starts"** (default off, default duration), mirroring `lockOnLaunch`.
9. **Battery guard** — default **on**: end Sessions while on battery when **either** charge ≤ 10 % **or** macOS reports `IOPSGetBatteryWarningLevel() == Final` (≈ 10 min of real runtime — a tired battery can hit 10 % with four minutes left), whichever lands first; notify. _Amended by research 01_: the OS warning level costs one enum read and no UI, and stops the guard lying on old hardware. Applies to Sessions only in v1; whether it should also cover the Lock hold is fog. **Research 02**: 10 % is Amphetamine's threshold, but Amphetamine ships the guard **off** — Medusa's **default on is a deliberate divergence**, because this audience leaves the Mac working unattended and a dead laptop is worse than a sleeping one. Amphetamine's sub-options (prompt before ending, restart on AC reconnect) stay out of v1.
10. **Notifications** — "Keep Awake ended" and "Ending in 5 minutes" with an **Extend** action, both default on, permission asked at first Session start. **Research 03 confirmed feasibility with four clauses**: (a) a bare `CFBundleIdentifier` is the whole requirement — `build-app.sh` already sets one, Sparkle is uninvolved; (b) `UNUserNotificationCenter.current()` **traps uncatchably** when unbundled (`swift run`, every `--self-test`/`--snapshot-*` entry point) — **invariant: nothing touches the center without a `Bundle.main.bundleIdentifier != nil` guard**; (c) delegate + categories register at launch, authorization is deferred, and `willPresent` must be implemented or notifications are silenced whenever `NSApp.activate` runs; (d) **no provisional authorization** (Apple: provisional lands silently in history — an Extend prompt nobody sees). The menu's `Extend ▸` is the guaranteed path because Banners-vs-Alerts is the user's setting. **Amended by research 02**: Amphetamine deleted manual start/end notifications in v4 ("manual start/end requires you to take some action" — the icon already changes) and notifies by default only for sessions the user did *not* start by hand; it has **no ending-soon warning at all**. Medusa therefore: **never** notifies on start or on a manual Stop; **"Keep Awake ended" fires only for un-chosen ends** (duration elapsed, end time passed, battery guard, process ended) — default **on**, copy modelled on Amphetamine's reason strings and closing with `Your Mac will sleep on its normal schedule`; the **"Ending in 5 minutes" + Extend nudge is a Medusa original and ships default off** (if you're touching the Mac it isn't idle, if you're away you won't see it — the one real case, watching output hands-off, is a toggle away).
11. **Menu bar** — one status item (no second icon). Icon reflects state (idle / awake / locked). Idle: `Keep Awake ▸` submenu of presets + Indefinitely + Until… + Custom…, and an "Allow display to sleep" check. Active: a disabled header line (`Awake · 1 h 23 m left` / `· indefinitely` / `· until 5:00 PM`, plus `also: lock` when the Lock hold is live), `Extend ▸` (+15 min / +30 min / +1 h), `Stop Keep Awake`. Optional countdown text beside the icon (Settings, default off). **Research 03**: width jitter is fixed by the **format**, not the font — the status-bar text is `1:23`/`0:59` in monospaced digits (the verbose `1 h 23 m` phrasing stays on the menu header only), ticked on the **minute boundary** so it never reads up to 59 s stale. SF Symbols verified against the on-disk catalog: all candidates (`cup.and.saucer`, `bolt`, `eye`, `moon.zzz`, `powersleep`) exist on macOS 13; only `cup.and.heat.waves` is out. `Until…`/`Custom…` open an `NSAlert` with an `NSDatePicker` accessory view — the pattern `AppDelegate` already uses twice; `NSMenuItem.view` hosting a picker is a run-loop-mode trap, `NSPopover` is post-v1 polish. **Added from research 02** (free parity): **right-click / ⌃-click on the status item = Quick start** — toggles a Session with the Default duration without opening the menu; left-click keeps showing the menu. Amphetamine's default mapping, and one-click keep-awake with zero new UI.
12. **Hotkey** — a second recordable chord (existing `ShortcutRecorder`) that toggles a Session with the default duration. Default **unassigned**: this audience's app chords are sacred (⌘⇧K is Xcode Clean).
13. **Presets** — default list 15 min · 30 min · 1 h · 2 h · 4 h · 8 h · **12 h**, editable in Settings; **Default duration** for Quick start **Indefinitely** (**Amphetamine parity confirmed verbatim** by research 02). Research 02 also showed Amphetamine's ladder is *fixed* (5–60 min by 5, 1–12 h, 24 h) plus a one-off "Other Time/Until…" sheet — so **editable Presets are a Medusa original**, kept because the user's ask was "make sure it's customizable" and six-to-seven editable rows beat 24 fixed ones in a menu. 12 h was added so overnight fits without Custom….
14. **Customizable means** — editable presets · default duration · default Awake level · battery guard on/off + threshold · notification toggles + lead time · hotkey · countdown in menu bar · start at launch · the existing "Keep Mac awake while locked" toggle **moves** to the new Keep Awake tab.
15. **Architecture direction (for the spec)** — `KeepAwakePolicy` pure decision surface + `scripts/keep-awake-loop.swift` red/green harness (repo pattern), `KeepAwakeController` owning the engine, `PowerAssertion` growing to **two assertion IDs** (display + system) created via `IOPMAssertionCreateWithProperties` with `TimeoutSeconds` + `TimeoutActionTurnOff` — **verified live by research 01**: the kernel disarms a hung Medusa at the deadline, and **Extend** is `IOPMAssertionSetProperty(id, kIOPMAssertionTimeoutKey, …)` on the same ID. Foundation `beginActivity` was rejected (same assertions underneath, no timeout, no handle). Gotcha: after a TurnOff timeout the assertion object still reports level On — `held` must be tracked from the deadline, not the object. `--self-test` keeps passing; harness keys on **pid** in `pmset -g assertions` and never calls the streaming `assertionslog`. ADR-0001 "one engine, many Holds" is written by the spec ticket.

### Facts (read before re-deriving)

- `Sources/Medusa/PowerAssertion.swift` — one `PreventUserIdleDisplaySleep` assertion, `begin/reaffirm/end`, `held` flag; owned by `LockController` (also instantiated by `SelfTest`). `LockController.lock(forceKeepAwake:)` + `LockPolicy.shouldHoldKeepAwake` decide whether to hold; reaffirm on wake; `onKeepAwakeFailed` alert fires at most once per lock.
- `AppSettings.Keys.keepAwake` (default `true`) is bound in `LockScreenPane` as "Keep Mac awake while locked"; defaults register in `AppSettings.registerDefaults()`.
- Settings: `SettingsWindowController.Tab` = General · Lock Screen · Permissions, each with a fixed `NSSize`; panes are SwiftUI `Form`s with `@AppStorage`. `--snapshot-settings` hangs headless — use `--snapshot-lockpane`-style single-pane runners for verification.
- `MenuBarController` — single `NSStatusItem` with `Lock Now/Unlock`, `Settings…`, `About`, `Check for Updates…` (inserted when updates supported), `Quit`; re-reads the hotkey label on `UserDefaults.didChangeNotification`.
- `HotKey` — non-consuming `NSEvent` global monitor reading `AppSettings` per event; `ShortcutRecorder` renders/records chords in General.
- `SystemLockPreemptMonitor` — polls HID idle every 2 s while enabled & unlocked; auto-lock calls `lock(forceKeepAwake: true)`.
- Harness pattern: pure `LockPolicy` enum + `scripts/unlock-trap-loop.swift` / `scripts/system-lock-preempt-loop.swift` (exit 0/1). `--self-test` asserts the power assertion is held.
- Build: SwiftPM only (no Xcode project), tools 6.0 / language mode 5, macOS 13 target, Sparkle dep; `scripts/build-app.sh` produces "Medusa Local" (`org.medusa.Medusa.local`), releases are `org.medusa.Medusa`. `swift run` is unbundled — anything needing a bundle id (notifications) must guard for that.
- Release pipeline: `scripts/release.sh` + `scripts/update-appcast.sh`; DMG for humans, zip for Sparkle; asset first, appcast push second.

## Out of scope

- **Triggers** (Wi-Fi network, IP, drive mounted, external display, power adapter, schedule, headphones/Bluetooth) — Amphetamine's automation layer; a separate effort if ever.
- **Closed-display / lid-closed mode** — needs Amphetamine-Enhancer-style hacks; thermal and safety risk; idle assertions cannot prevent forced sleep. Never-trap and the OLED work stay untouched.
- **Drive Alive**, file-download monitoring, screen-saver control.
- **AppleScript / Shortcuts / URL-scheme automation.**
- **Session history / statistics**, custom icon packs, sounds.
- **End-of-session actions** beyond notify (sleep / lock / shut down on end).
- Amphetamine sub-features surfaced by [research 02](research/02-amphetamine-audit.md) and ruled out of v1: **prompt before the Battery guard ends a Session**, **restart a Session on AC reconnect**, **periodic Session Reminders**, **"Use timer vs system clock" preference** (deadline is hardcoded), **screen-saver control**, **cursor jiggle**, **Lock screen after inactivity** (Preempt already owns that ground).
- Replacing `caffeinate` for terminal users; a security-boundary claim of any kind.
